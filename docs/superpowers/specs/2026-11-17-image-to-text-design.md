# Скилл `image-to-text`: надёжное чтение текста с изображений

Дата: 2026-11-17
Статус: на утверждении

## Зачем

Агент без нативного зрения должен читать текст с картинок и не врать. Текущий скилл
`image-to-text-understanding` сравнивает бинаризованные пятна с растровыми шаблонами
глифов (5×7…13×15) без словаря и без языковой модели — отсюда систематическая путаница
слов. Замена: настоящий OCR-движок (Tesseract 5.5.4) + препроцессинг + явные пометки
неуверенности.

Проверка на реальном файле (`eMake-and-Draw/docs/screenshot.png`, 782×460):
сырой вызов — 26 слов, mean conf 76.5; с апскейлом ×2 — 44 слова, mean conf 82.7.
Значит основной выигрыш даёт подготовка изображения, а не смена настроек OCR.

## Цели

- Читать текст со скриншотов, интерфейсов, документов, PDF на `rus+eng` с координатами
  и уверенностью по каждому слову.
- Отдавать результат в двух видах: компактный Markdown для чтения агентом и JSON
  с bbox/conf для точных ссылок («слово в строке 3, bbox …»).
- Помечать ненадёжное как ненадёжное: слово ниже порога не исправляется молча,
  а попадает в `uncertain` с вариантами-кандидатами.
- Быть проверяемым: бенчмарк CER/WER на наборе тестовых изображений.

## Не-цели

- Описание сцен, объектов, лиц, «что происходит на фото».
- Рукописный текст (best effort, без гарантий).
- Восстановление таблиц в структуру (в v1 — только текст).
- Языки кроме `rus`/`eng` в v1 (список настраивается флагом).

## Анти-цели

- Подставлять правдоподобное слово вместо нечитаемого.
- Возвращать «гладкий» текст без указания уверенности.
- Тяжёлые зависимости (torch, paddle), sudo, сеть во время работы.

## Ограничения среды

- Fedora 45, Python 3.15.2: `onnxruntime` недоступен → RapidOCR/ONNX-OCR отпадают.
- Установлено: `tesseract 5.5.4`, `tesseract-langpack-{rus,eng}`, `hunspell` + словари
  `ru_RU`/`en_*`, `pdftoppm`, ImageMagick.
- В Python: `Pillow`, `numpy`, `RapidFuzz`. `cv2` нет и не нужен.
- Работа только офлайн, через CLI `tesseract` и разбор TSV.

## Рассмотренные подходы

- **A. Tesseract + препроцессинг + постобработка** — выбран. Офлайн, 0.5–2 с на
  скриншот, координаты и confidence из TSV, ноль новых зависимостей.
- **B. EasyOCR на torch** — лучше на фото и изогнутом тексте, но +300 МБ и 5–20 с на
  CPU; на скриншотах выигрыша над A нет. Отклонён.
- **C. Гибрид с моделью зрения** — фактически A плюс честное «описание сцены
  недоступно». Взят как раздел границ применимости в A.
- **D. Патчить старый скилл** — отклонён: сопоставление с шаблонами глифов не лечится.

## Устройство

```
~/.config/opencode/skills/image-to-text/
  SKILL.md          # триггер, рабочий процесс, формат отчёта, границы
  scripts/see.py    # CLI: изображение/PDF → JSON + Markdown
  scripts/bench.py  # CER/WER по tests/
  tests/            # картинки + эталонный текст
```

Старый скилл остаётся нетронутым для сравнения.

### Контракт `see.py`

```
see.py IMAGE [--json] [--md] [--langs rus+eng] [--psm auto|3|6|11]
             [--scale auto|1..4] [--crop x,y,w,h] [--tile 2x2]
             [--min-conf 70] [--suggest on|off]
```

Выход: `{readable, meta{size,scale,polarity,psm,langs,mean_conf}, blocks[],
uncertain[], markdown}`. Блок: `{bbox, kind, conf, lines[{bbox,text,words[{text,conf,bbox,suggest[]}]}]}`.

### Этапы

1. **Загрузка.** PNG/JPEG/WebP — Pillow. PDF — `pdftoppm -r 200` (v1: первые 5 страниц).
   SVG — `magick` в растр, иначе ошибка с понятным сообщением.
2. **Полярность.** Средняя яркость рамки → тёмная/светлая тема; оба варианта
   прогоняются, если первый дал low-conf >25 %.
3. **Масштаб.** `min(w,h) < 1200` → ×2, иначе ×1.5; после первого прохода при
   mean_conf < 75 пробуется ×3. Потолок 6000 px по стороне.
4. **Контраст.** Grayscale + растяжение по перцентилям 2–98 (не min/max).
5. **OCR.** Первый прогон `--psm 3`; оценка `score = mean_conf × log(1+words)`.
   Если score ниже порога или доля conf<70 больше 25 % — прогоны `--psm 6` и `--psm 11`,
   выбирается лучший score. Выбранный psm попадает в `meta`.
6. **Сборка.** Группировка TSV по `block_num/par_num/line_num`, объединение bbox,
   текст строки с учётом межсловных пробелов, порядок чтения — как выдал движок.
7. **Структура (эвристики).** heading — высота строки >1.25× медианы; list — маркер
   `•/-/*/1.` с малым отступом; code — моноширинность (близкие ширины символов при
   длине слова ≥3). Больше в v1 не обещаем.
8. **Подсказки.** Для слов с conf < порога: проверка по словарю hunspell
   (`ru_RU`, `en_*`); если слова нет — кандидаты через RapidFuzz (редакционное
   расстояние 1–2, score ≥85) кладутся в `suggest`. **Автозамены нет.**
9. **Отчёт.** `readable: false`, если mean_conf < 60 или слов < 3. Отдельный список
   `uncertain` с bbox, чтобы агент мог перепроверить кропом.

### Правила в SKILL.md

- Всегда запускать `see.py`; не писать собственное распознавание глифов.
- Текст брать дословно из JSON; правки делать только по контексту и явно помечать.
- `uncertain` не додумывать: сообщать как есть с вариантами.
- Для фото и сцен прямо писать, что скилл читает только текст.
- При плохом результате — предписанная эскалация: ×2/×3, `--crop`, затем `--tile`.

## Проверка

`bench.py` считает CER/WER на `tests/`: скриншот eMake-and-Draw, тёмная тема чата,
иконка с текстом, документ. Цель v1: WER < 8 % на скриншотах. Базовая линия — вывод
старого скилла на тех же файлах.

## Что оставлено на усмотрение исполнителя

Точные пороги (масштаб, score, conf), набор эвристик структуры, состав `tests/`
и формат эталонов. Всё измеряемое — подгоняется по бенчмарку, не «на глаз».
